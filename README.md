# Packet Capture & Protocol Analysis Lab

## Overview

This project is a hands-on packet capture and protocol analysis lab using Kali Linux and Metasploitable 2 in an isolated VMware lab environment.

The lab demonstrates how network traffic can be captured, analyzed, and interpreted using `tcpdump` and `tshark`. It covers common protocols such as ICMP, DNS, HTTP, FTP, Telnet, and Nmap SYN scan traffic.

The main purpose of this project is to understand how different protocols appear at packet level and how insecure plaintext protocols can expose sensitive data such as usernames, passwords, commands, and session output.

All traffic was generated inside a local authorized lab environment only.

---
## Lab Objectives

The objectives of this lab were to:

- Capture network traffic using `tcpdump`.
- Analyze packet capture files using `tshark`.
- Understand ICMP echo request and reply traffic.
- Analyze DNS query and response behavior.
- Capture HTTP traffic and identify GET requests and 200 OK responses.
- Demonstrate how FTP transmits credentials in plaintext.
- Demonstrate how Telnet exposes login data, commands, and command output in plaintext.
- Analyze Nmap SYN scan behavior at packet level.
- Connect service enumeration knowledge from Nmap with packet-level analysis.
- Document evidence in a structured GitHub portfolio project.

## Methodology

For each protocol, traffic was generated from Kali Linux to the Metasploitable target machine. `tcpdump` was used to capture the traffic into `.pcap` files, and `tshark` was used to analyze the captures from the terminal.

General workflow:

```text
1. Start tcpdump capture
2. Generate traffic from Kali to Metasploitable
3. Stop tcpdump
4. Analyze the capture using tshark
5. Save evidence output
6. Document the security lesson
```

## Part 1: ICMP Packet Capture

ICMP traffic was generated using `ping`.

### Capture Command

```bash
sudo tcpdump -i eth0 icmp -w captures/01-icmp-ping.pcap
```

### Traffic Generation

```bash
ping -c 5 192.168.153.129
```

### Analysis Command

```bash
tshark -r captures/01-icmp-ping.pcap -Y "icmp"
```

### Key Observation

The capture showed ICMP echo request and echo reply packets between Kali and Metasploitable.

```text
192.168.153.128 → 192.168.153.129 ICMP Echo request
192.168.153.129 → 192.168.153.128 ICMP Echo reply
```

### Learning Outcome

ICMP is commonly used for connectivity testing. Unlike HTTP, FTP, or SSH, ICMP does not use application ports. The operating system network stack responds to ICMP echo requests.

### Evidence File

```text
evidence/01-icmp-analysis.txt
```

## Part 2: DNS Packet Capture

DNS traffic was generated by querying the DNS service running on Metasploitable.

### Capture Command

```bash
sudo tcpdump -i eth0 port 53 -w captures/02-dns-traffic.pcap
```

### Traffic Generation

```bash
dig @192.168.153.129 example.com
```

### Analysis Command

```bash
tshark -r captures/02-dns-traffic.pcap -Y "dns"
```

### Key Observation

The capture showed a DNS query from Kali and a DNS response from Metasploitable.

```text
192.168.153.128 → 192.168.153.129 DNS query for example.com
192.168.153.129 → 192.168.153.128 DNS response
```

The DNS response returned a server failure, which means the DNS communication happened, but Metasploitable could not resolve the external domain.

### Learning Outcome

DNS is used to resolve domain names to IP addresses. DNS traffic can reveal what domains a system is trying to access unless encrypted DNS is used.

### Evidence File

```text
evidence/02-dns-analysis.txt
```

## Part 3: HTTP Packet Capture

HTTP traffic was generated using `curl` against the web server running on Metasploitable.

### Capture Command

```bash
sudo tcpdump -i eth0 port 80 -w captures/03-http-traffic.pcap
```

### Traffic Generation

```bash
curl http://192.168.153.129
```

### Analysis Commands

```bash
tshark -r captures/03-http-traffic.pcap -Y "http"
tshark -r captures/03-http-traffic.pcap -Y "http.request" -T fields -e frame.number -e ip.src -e ip.dst -e http.request.method -e http.host -e http.request.uri
tshark -r captures/03-http-traffic.pcap -Y "http.response" -T fields -e frame.number -e ip.src -e ip.dst -e http.response.code -e http.response.phrase
```

### Key Observation

The capture showed the TCP handshake, HTTP request, and HTTP response.

```text
TCP handshake:
SYN → SYN/ACK → ACK

HTTP request:
GET / HTTP/1.1

HTTP response:
HTTP/1.1 200 OK
```

### Learning Outcome

HTTP traffic is transmitted in plaintext. Packet analysis can reveal request methods, hosts, URIs, response codes, and other web communication details when encryption is not used.

### Evidence File

```text
evidence/03-http-analysis.txt
```

## Part 4: FTP Plaintext Credential Analysis

FTP traffic was captured while logging into the FTP service on Metasploitable.

### Capture Command

```bash
sudo tcpdump -i eth0 port 21 -w captures/04-ftp-plaintext.pcap
```

### Traffic Generation

```bash
ftp 192.168.153.129
```

Lab credentials used:

```text
Username: msfadmin
Password: msfadmin
```

### Analysis Commands

```bash
tshark -r captures/04-ftp-plaintext.pcap -Y "ftp"
tshark -r captures/04-ftp-plaintext.pcap -Y "ftp" -T fields -e frame.number -e ip.src -e ip.dst -e ftp.request.command -e ftp.request.arg -e ftp.response.code -e ftp.response.arg
```

### Key Observation

The capture exposed the username and password in plaintext.

```text
USER msfadmin
PASS msfadmin
230 Login successful
```

### Learning Outcome

FTP transmits usernames, passwords, and commands in plaintext. If FTP traffic is captured on the network, credentials can be exposed.

### Security Recommendation

Use encrypted alternatives such as:

```text
SFTP
FTPS
SSH-based file transfer
```

### Evidence File

```text
evidence/04-ftp-plaintext-analysis.txt
```

## Part 5: Telnet Plaintext Session Analysis

Telnet traffic was captured while logging into Metasploitable.

### Capture Command

```bash
sudo tcpdump -i eth0 port 23 -w captures/05-telnet-plaintext.pcap
```

### Traffic Generation

```bash
telnet 192.168.153.129
```

Lab credentials used:

```text
Username: msfadmin
Password: msfadmin
```

Commands executed after login:

```bash
whoami
pwd
exit
```

### Analysis Commands

```bash
tshark -r captures/05-telnet-plaintext.pcap -Y "telnet"
tshark -r captures/05-telnet-plaintext.pcap -q -z follow,tcp,ascii,0
```

### Key Observation

The Telnet ASCII stream showed readable login prompts, username characters, password characters, shell commands, and command output.

Captured session data included:

```text
metasploitable login:
msfadmin

Password:
msfadmin

whoami
msfadmin

pwd
/home/msfadmin
```

### Learning Outcome

Telnet transmits interactive session data in plaintext. Packet analysis can reveal usernames, passwords, shell commands, and command output.

### Security Recommendation

Use SSH instead of Telnet for remote administration.


## Part 6: Nmap SYN Scan Traffic Analysis

Nmap scan traffic was captured to understand how port scanning appears at packet level.

### Capture Command

```bash
sudo tcpdump -i eth0 host 192.168.153.129 -w captures/06-nmap-scan-traffic.pcap
```

### Traffic Generation

```bash
nmap -sS -p 21,22,23,80 192.168.153.129
```

### Analysis Commands

```bash
tshark -r captures/06-nmap-scan-traffic.pcap
tshark -r captures/06-nmap-scan-traffic.pcap -Y "tcp.flags.syn == 1 && tcp.flags.ack == 0" -T fields -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport
tshark -r captures/06-nmap-scan-traffic.pcap -Y "tcp.flags.syn == 1 && tcp.flags.ack == 1" -T fields -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport
```

### Key Observation

The capture showed SYN packets from Kali to multiple ports on Metasploitable.

```text
Kali → Metasploitable: SYN packets to ports 21, 22, 23, 80
Metasploitable → Kali: SYN/ACK responses from ports 21, 22, 23, 80
Kali → Metasploitable: RST packets
```

The SYN/ACK responses indicate that the scanned ports were open.

### Learning Outcome

Nmap SYN scans can be identified by connection attempts to multiple ports. In a SYN scan, Nmap sends SYN packets and uses the target's response to determine whether a port is open, closed, or filtered.

### Security Recommendation

Network defenders can monitor for repeated connection attempts across multiple ports as possible port scanning behavior.

### Evidence File

```text

```

## tcpdump Filter Explanation

Different capture filters were used depending on the goal.

### Port-based filter

Used when analyzing one specific protocol or service:

```bash
sudo tcpdump -i eth0 port 80 -w captures/http.pcap
```

Examples:

```text
port 53 → DNS
port 80 → HTTP
port 21 → FTP
port 23 → Telnet
```

### Host-based filter

Used when capturing all traffic involving one machine:

```bash
sudo tcpdump -i eth0 host 192.168.153.129 -w captures/target-traffic.pcap
```

This was useful for Nmap analysis because multiple ports were scanned.

### Combined host and port filter

Can be used when capturing one service on one specific host:

```bash
sudo tcpdump -i eth0 host 192.168.153.129 and port 80 -w captures/target-http.pcap
```

## Security Recommendations

- Use HTTPS instead of HTTP for web traffic.
- Use SFTP or FTPS instead of FTP.
- Use SSH instead of Telnet.
- Avoid transmitting credentials over plaintext protocols.
- Monitor networks for repeated connection attempts across multiple ports.
- Use packet capture tools responsibly and only in authorized environments.
- Segment lab environments from real networks when working with intentionally vulnerable machines.
- Never expose Metasploitable or similar vulnerable VMs to public or untrusted networks.
